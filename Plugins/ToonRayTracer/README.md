# ToonRayTracer

UE5.8 のハードウェアレイトレーシング（DXR）を使ったトゥーンシェーダーのプラグイン。
『Ray Tracing in One Weekend』の第11章までをシーンの TLAS 上で実装し、その仕組みの上にトゥーンシェーディングを構築している。

- SceneViewExtension の `SubscribeToPostProcessingPass`（Tonemap）でパスを追加する（トーンマップの後に実行される）
- Renderer の Private ヘッダーは使わず、Public API（`FXRenderingUtils` など）だけで実装している

## 動作条件

- プロジェクト設定でハードウェアレイトレーシングが有効（`r.RayTracing=True`）
- Substrate が無効（`r.Substrate=False`）。滑らかな法線を GBufferA から読むため
- シーンにレイトレーシング用の TLAS が構築されていること。構築されていないフレームでは何もせず元の画像を返す

## 設定パネル

メニューの「ウィンドウ」→「ToonRayTracer」で設定パネルを開ける（エディタ専用モジュール `ToonRayTracerEditor`）。

- 下記のコンソール変数をすべてパネルから変更できる（ドロップダウン、スライダー、カラーピッカー）。変更はすぐ画面に反映される
- 値はプロジェクトのユーザー設定（`Saved/Config/.../EditorPerProjectUserSettings.ini`）に保存され、次回起動時にも引き継がれる
- 「蓄積をリセット」：フレーム間の蓄積をやり直す（レベル上のオブジェクトを動かしたあとに使う）
- 「コンソールの値を読み込む」：コンソールで変更した値をパネルに反映する
- 「初期値に戻す」：すべての設定を初期値に戻す
- 「環境：朝 / 昼 / 夕方 / 夜」：レベルの Directional Light と Skylight を、時間帯ごとの設定に切り替える（トゥーンの見え方を色々な環境で確かめるため。Ctrl+Z で元に戻せる）

  | 時間帯 | Directional Light（太陽の高さ・色・強さ） | Skylight |
  |---|---|---|
  | 朝 | 15°・淡い暖色・6 lux | 少し青みのある白 |
  | 昼 | 60°・白・10 lux | 白 |
  | 夕方 | 6°・橙色・4 lux | 暖色 |
  | 夜 | 40°・白に近い青の月の光・0.5 lux（空の太陽として使わないので空は暗くなる） | 青みのある弱い光 |

## 表示モード

`r.ToonRayTracer.ShadingMode` で切り替える。

| 値 | 内容 |
|---|---|
| 3 | トゥーンシェーディング（既定） |
| 0 | 確認用：当たった面の法線を色で表示 |
| 1 | 確認用：本の第9〜11章のマテリアル（拡散反射・金属・ガラス）。ランダムなレイを使うのでノイズが出る |
| 2 | 確認用：Directional Light による N・L のなめらかな陰影 |

`r.ToonRayTracer.TraceMode` で交差判定の対象を切り替えられる。

| 値 | 内容 |
|---|---|
| 1 | シーンのメッシュ（TLAS）に TraceRay（既定） |
| 0 | シェーダー内の解析的な球（本の第11章のシーン。ワールド原点付近に配置）。地面は『The Next Week』第4章のチェッカー、中央の球は第5章の Perlin ノイズによる大理石模様 |

解析的な物体のシーンは `r.ToonRayTracer.AnalyticScene` で切り替える（パネルの「解析的な物体のシーン」）。

| 値 | 内容 | 本のカメラに相当する UE の位置 |
|---|---|---|
| 0 | 本の第11章のシーン（上記） | (-50, 0, 50) 付近から +X 方向 |
| 1 | 『The Next Week』第7章 simple_light。大理石の地面と球を、四角形のライトと球のライトだけで照らす（背景は黒） | (600, 2600, 300) から (0, 0, 200) を見る |
| 2 | 『The Next Week』第7章 コーネルボックス（第6章の四角形で組み立て、天井の四角形のライトだけで照らす。背景は黒） | (-800, 278, 278) から +X 方向 |
| 3 | 『The Next Week』第8章 箱を置いたコーネルボックス（回転・移動した 2 つの白い箱） | (-800, 278, 278) から +X 方向 |
| 4 | 『The Next Week』第9章 cornell_smoke（2 つの箱を黒い煙と白い煙にしたもの） | (-800, 278, 278) から +X 方向 |
| 5 | 『The Next Week』第10章 final_scene の簡易版（地面の箱の格子、ガラス・金属・大理石・中が濁ったガラスの球、全体を包む薄い霧）。オレンジの球は第2章の移動ブラーで動く。1000 個の小さな球の塊は、第3章の BVH（CPU で組み立てた入れ子の箱を、シェーダーでスタックを使ってたどる）で探す。地球の球には、第4章の画像テクスチャで `r.ToonRayTracer.ImageTexture` のテクスチャ（既定は `/ToonRayTracer/Textures/T_EarthMap`）を貼る。見つからなければ UV のチェッカーで代用する | (-600, 478, 278) から Yaw -18.4 度の方向 |
| 6 | 『The Rest of Your Life』第12章の最終シーン。コーネルボックスに、アルミ（金属）の背の高い箱とガラスの球を置く。確認用の「本の第9〜11章」モードで、拡散反射の方向の選び方を「混合」にすると、天井のライトとガラスの球を狙ってレイを飛ばす | 2 と同じ |

光る物体だけで照らすシーンは、表示モードを「確認用：本の第9〜11章」にすると本と同じ見た目になる。
ノイズが非常に多いため、蓄積フレーム数の上限を 1024 以上、反射回数の上限を 50 にして、しばらく待つ。
トゥーン表示では、光る物体はその光の色で塗られ、それ以外は Directional Light で照らされる。
煙は、トゥーン表示では通る距離から求めた不透明度を 4 段階に区切った「セル画風の霧」として塗る（ノイズが出ない）。
煙の明暗は、煙に入った位置のすぐ先から光源が見えるかで決める。
煙はトゥーンのシャドウレイでは無視する（くっきりした影を落とさない）。

## メッシュごとの設定（Custom Primitive Data）

何も設定しなくても、カメラから見えている面は UE のマテリアルの色（GBuffer のベースカラー）でトゥーンの塗りになる。
メタリックが高くつやのある（ラフネスが小さい）マテリアルは、自動で鏡面反射の金属になる。
Custom Primitive Data は、マテリアルの種類（金属・ガラス）や影色、ハイライトなどを上書きしたいメッシュにだけ設定する。

メッシュの詳細パネルの「Custom Primitive Data」→「Data」に要素を追加して設定する。
使わない項目は 0 のままでよい（0 は「未設定」として扱う）。
`[0]` に種類を指定したメッシュは、`[1][2][3]` の色が UE のマテリアルの色より優先される。

| Index | 内容 | 値の範囲 | 未設定（0）のとき |
|---|---|---|---|
| 0 | マテリアルの種類（1: ランバート, 2: 金属, 3: ガラス） | 0 ～ 3 | UE のマテリアルの色のランバート（反射・屈折の先など GBuffer がない場所では 50% の灰色） |
| 1, 2, 3 | 素材の色（R, G, B） | 0 ～ 1 | 黒（種類を設定した場合） |
| 4 | 金属のぼけ具合（ShadingMode 1 のみ） | 0 ～ 1 | ぼけなし |
| 5 | ガラスの屈折率 | 1 以上 | 1.5 |
| 6, 7, 8 | トゥーンの影色（R, G, B）。素材の色に掛ける | 0 ～ 1 | `r.ToonRayTracer.Toon.ShadowColor` |
| 9 | トゥーンのハイライトの強さ | 0 ～ 1 | ハイライトなし |
| 10 | トゥーンのリムライトの強さ | 0 以上 | リムライトなし |
| 11 | トゥーンの線の太さ（ピクセル）。負の値なら線を引かない | 0 より大きい値 / 負の値 | メッシュの種類ごとの太さ（`OutlineWidth` / `OutlineWidthSkinned`） |
| 12 | キャラクターとして扱うか。正の値なら扱う、負の値なら扱わない。`CharacterOnly` でトゥーンで塗るか、`CharacterSelfShadow` の対象になるかに影響する | 正の値 / 負の値 | スケルタルメッシュをキャラクターとする |
| 13 | 髪越しに見せるパーツ（眉毛など）のマテリアルスロットを、このメッシュだけ上書きする。スロット番号 n のパーツを見せるなら 2^n を足した値（例：スロット 4 なら 16）。`SeeThroughSlotMask` を参照。プロファイルで髪越しに見せるスロットを指定したキャラクターでは使わない | 正の整数 | `SeeThroughSlotMask` |
| 14 | Toon Character コンポーネントが書き込むキャラクターの番号（手で設定しない） | - | - |

例：銀色の鏡面の球でハイライトあり → `2, 0.8, 0.8, 0.8, 0, 0, 0, 0, 0, 1, 0`

## キャラクターごとの設定（Toon Character Profile / Toon Character コンポーネント）

顔の影・目の表現・前髪の影・眉毛の透けは、パーツをマテリアルスロットで、顔の向きと大きさを頭と両目のボーンで見分ける。
スロットやボーンの名前、顔の大きさはモデルごとに違うため、モデルごとにプロファイルを作って設定する。

1. コンテンツブラウザで「その他」→「データアセット」→「Toon Character Profile」を作る（モデルごとに 1 つ）
2. プロファイルの「対象のモデル」にスケルタルメッシュを入れ、「候補を自動で入れる」を押す
   （ボーンとパーツの候補、大きさの項目に全体の設定から求めた倍率、見た目の項目に今の全体の設定が入る。
   大きさと見た目は「大きさに全体の設定を入れる」「見た目に全体の設定を入れる」で入れ直せる）
3. 足りないところや間違いを直す（ボーンとスロットは、対象のモデルの名前から選べる）
4. キャラクターのアクターに「Toon Character」コンポーネントを追加し、「プロファイル」にそのプロファイルを選ぶ

同じモデルを何体置いても、別のレベルでも、同じプロファイルを使い回せる。
コンポーネントを付けていない（プロファイルを選んでいない）キャラクターは、全体の設定を使う。

| 項目 | 内容 | 空や 0 のとき |
|---|---|---|
| 頭のボーン / 左目のボーン / 右目のボーン | 顔の位置と向き、大きさの基準になる両目の間の距離を求めるボーン | 全体の設定（`FaceHeadBone` など） |
| 顔 / 目 / 髪 / 髪越しに見せるスロット | 各表現の対象にするパーツ。マテリアルスロットの名前で指定する（スロットの順番が変わってもずれない） | 全体の設定（スロット番号） |
| 目の三角形の開始番号・終了番号 | 目のスロットの中で、目として扱う三角形の範囲（終了番号が 0 なら最後まで） | 目のスロットが空なら全体の設定 |
| 大きさ（両目の間の距離に対する倍率） | 顔の半分の幅、顔の境目のぼかし、上まぶたの影の太さ、瞳のハイライトの探す距離、前髪の影の幅と探す距離、眉毛の透けの探す距離 | 全体の設定（cm）を大きさの基準で拡大縮小した値 |

| 見た目（チェックを入れた項目だけ） | 影色、肌の影色、影の色の鮮やかさ、線の太さ、線の色の倍率、リムライトの強さと幅、顔の境目の曲がりと前からの光の補正、上まぶたの影の明るさ、瞳のハイライトの強さとしきい値、前髪の影の濃さと光の側へのずらし、眉毛の透けの濃さと明るさ | 全体の設定（「見た目に全体の設定を入れる」で今の全体の設定を写せる） |

- 目のスロットには、瞳の前に重なる透過のパーツ（ハイライトや模様の板）も入れる。目の判定のレイがその板で止まるため
- Toon Character コンポーネントは、キャラクターの番号を同じアクターのスケルタルメッシュの Custom Primitive Data の `[14]` に書き込む（手で設定しない）。
  シェーダーはこの番号で、体や服の点からもそのキャラクターの見た目の設定を見つける
- スロットは 0 ～ 63 番（LOD 0 のセクションの番号）まで使える。全体の設定は 0 ～ 31 番
- 設定は、顔（頭と両目のボーンを持つスケルタルメッシュ）ごとに求めてシェーダーへ渡し、シェーダーは点の近くの顔の設定を使う。
  目・顔・髪・眉毛はどれも頭の周りにあるので、点の位置でキャラクターを見分けられる（同時に扱える顔は 8 つまで）

### 大きさの基準（`ReferenceEyeDistance`）

全体の設定の幅や距離（cm）は、ある大きさのキャラクターに合わせた値になっている。
`r.ToonRayTracer.Toon.ReferenceEyeDistance` にそのキャラクターの両目の間の距離（cm）を入れると、
ほかのキャラクターでは両目の間の距離に比例して幅や距離を拡大縮小する（0 なら拡大縮小しない）。
両目の間の距離は、Toon Character コンポーネントの「両目の間の距離（cm）」で確認できる。

例（MMD のモデルを Blender の MMD Tools で FBX にしたもの）：頭のボーン `頭`、左目のボーン `目_L`、右目のボーン `目_R`（FBX にするとボーン名の「.」が「_」になる）。
目のスロットには、白目と瞳に加えて、瞳の前に重なるハイライトや模様の板のスロットも入れる

## コンソール変数

### トゥーンシェーディング（`r.ToonRayTracer.Toon.*`）

| 変数 | 既定値 | 内容 |
|---|---|---|
| `CharacterOnly` | 0 | トゥーンで塗るのをキャラクター（スケルタルメッシュ）だけにし、背景は通常描画（Lumen など）のままにする（鳴潮風のルック）。メッシュごとに Custom Primitive Data の `[12]` で上書きできる。ShadingMode 3（トゥーン）、TraceMode 1（シーン）のときに有効 |
| `BeforeTSR` | 1 | `CharacterOnly` のとき、TSR の前（描画解像度、トーンマップ前の HDR）に描く。ピクセル中心に 1 本だけレイを飛ばし（TAA のジッターはカメラの行列に含む）、アンチエイリアス・アップスケール・フレームをまたいだ平均は TSR に任せる。動いている間の輪郭のギザつきが抑えられ、トーンマップ・DOF・ブルームも背景と同じようにかかる。自前の蓄積と動きの判定は使わない。0 ならトーンマップの後（出力解像度）に描く |
| `InverseTonemap` | 1 | `BeforeTSR` のとき、UE のトーンマップ（Filmic）の逆と露出の逆をかけた色を書き込み、トーンマップの後に描いた場合と同じ色味にする。色域の拡張・ブルーム・ビネットは打ち消さないため近似。0 なら背景と同じようにトーンマップがかかる |
| `CharacterSelfShadow` | 0 | キャラクターが自分自身の影を受けるか。0 ならキャラクターの面からのシャドウレイは自分自身を通り抜け、背景や小物など、ほかの物体の影だけ受ける（服のシワや重なりのまだらな影、顔に落ちる前髪や頭の影が消える） |
| `Skin` | 1 | UE のマテリアルのシェーディングモデルが Subsurface / Preintegrated Skin / Subsurface Profile の面を肌とし、下の肌用の境目と影色で塗る。顔のマテリアルのシェーディングモデルをこれらにして使う |
| `SkinShadowThreshold` | -0.3 | 肌の影との境目の N・L。`ShadowThreshold` より下げると、顔に細かい影が入りにくくなる |
| `SkinShadowColor` | `0.75,0.5,0.5` | 肌の影色（線形の R,G,B）。赤みのある影にする。メッシュごとの影色（Custom Primitive Data）より優先する |
| `CharacterRimStrength` | 1.5 | キャラクターのリムライトの強さ。画面上で光源の方向へ `CharacterRimWidth` ずらした位置が十分奥（背景や空）なら、光源の側の輪郭とみなし、素材の色 × ライトの色で明るい縁を加える。面の向きではなく深度の差で判定するため、縁の幅が一定になる。0 なら入れない |
| `CharacterRimWidth` | 2.5 | キャラクターのリムライトの幅（ピクセル） |
| `CharacterOutlineColorScale` | 0.25 | キャラクターの線を、黒ではなく素材の色にこの値を掛けた色にする（色つきの線）。0 なら `OutlineColor` |
| `SeeThroughOpacity` | 0.25 | 眉毛の透け。キャラクターの髪に当たったピクセルで、同じキャラクターのまま奥へ `SeeThroughDistance` 以内に、Custom Primitive Data の `SeeThroughSlotMask`（メッシュごとには Custom Primitive Data の `[13]`）で指定したパーツがあれば、髪の色を `SeeThroughBrightness` 倍に暗くした色をこの割合で重ね、前髪の上に眉毛の形を見せる。パーツはマテリアルスロット（レイトレーシングのジオメトリ番号）で判定する。肌の奥は透かさない。0 なら透かさない |
| `SeeThroughBrightness` | 0.5 | 眉毛が透けている部分の、髪の色の倍率（0 で黒、1 で変えない） |
| `SeeThroughDistance` | 20.0 | 髪の奥を探す距離（cm）。大きすぎると頭の反対側のパーツまで透ける |
| `EyeSlotMask` | 16 | キャラクターの目として扱うパーツのマテリアルスロット（スロット番号 n なら 2^n。初期値はエレメント 4）。パネルではスロット番号の一覧で指定する |
| `EyeTriangleStart` | 1850 | 目のスロットの中で、目として扱う最初の三角形の番号（初期値は確認に使っているキャラクターで、眉毛とまつ毛を除いた値）。眉毛が目と同じスロットにある場合に、目の部分だけを選ぶ。`r.ToonRayTracer.Debug.Geometry 3` で、目が緑・それ以外が赤になるように調整する |
| `EyeTriangleEnd` | 0 | 目として扱う三角形の範囲の終わり（この番号は含まない）。0 なら最後まで |
| `EyeShadowDistance` | 2.0 | 上まぶたの影。目の点を上方向（ワールドの Z 軸）へこの距離（cm）だけずらした位置をカメラから見て、まだ目が見えていれば影なし、まぶた・まつ毛・前髪などが見えていれば影にする。目の見えている部分の上の縁に沿って、まぶたの形の帯状の影ができる。大きいほど帯が太くなる。0 なら影なし |
| `EyeShadowBrightness` | 0.7 | 上まぶたの影の部分の明るさの倍率（1 なら影なし） |
| `FaceShadow` | 1 | 顔の影。顔の明暗を、面の向きではなく、頭の向きと光の向きから計算した境目で決める（SDF の顔影と同じ動き方）。光が正面なら顔全体が明るく、真横なら光の側の半分、真後ろなら顔全体が影になり、その間は境目がまっすぐ顔の上を左右に動く。横や後ろから光が当たったときの顔の不規則な明暗が出ない。顔の向きは頭と両目のボーンの位置から毎フレーム求める（ボーンの軸の向きは使わない）。ほかの物体が落とす影は残る |
| `FaceSlotMask` | 8 | 顔として扱うパーツのマテリアルスロット（スロット番号 n なら 2^n。初期値はエレメント 3）。パネルではスロット番号の一覧で指定する |

## 注意点

- カメラ・表示範囲・上記の設定・ライトが変わると蓄積は自動でリセットされる
- 動く物体は `r.ToonRayTracer.DetectMotion` で検出し、そのピクセルだけ蓄積をやり直す
  - 速度を書き込む物体（可動の物体、アニメーションするスケルタルメッシュなど）が見えているピクセルとその周囲（アウトラインの太さ分）と、
    深度が変わったピクセル（物体が動いて後ろが見えた、など）が対象
  - 物体が動いている間は、ピクセルの中心で「見えている物体・光が届くか・反射した先の物体」を毎フレーム調べ、
    変わったピクセル（動く物体の影が落ちてきた、鏡に映り込んだ、など）だけ蓄積をやり直す
  - それでも残る細かな残像（影の境目の 1 ピクセル幅、ガラスに透けて見える物体など）のため、
    物体が動いている間は全ピクセルの蓄積数を `MotionMaxAccumulatedFrames` までに抑える
  - 影や映り込みだけが変わる場合（ライトの色の変化、画面外の物体の移動など）は検出できない。
    残像が残ったら設定パネルの「蓄積をリセット」を押す（コンソールでは `r.ToonRayTracer.ResetAccumulation` の値を変える）
- シェーダー（`.usf`）だけを変更した場合は、エディタのコンソールで `recompileshaders changed` を実行すれば反映される。
  C++ を変更した場合は、エディタを閉じてからビルドする（Live Coding が有効な間は外部からビルドできない）
- 滑らかな法線と UE のマテリアルの色が使えるのは、カメラから見えている点だけ（反射・屈折の先も、画面内に見えていれば使う）。
  画面外や、手前の物体に隠れている点は、その物体の代表色（これまでにカメラから見えた部分の UE のマテリアルの色の平均）で塗る。
  テクスチャの模様は再現されず、1 色になる。一度も画面に映っていない物体は Custom Primitive Data の色（未設定なら 50% の灰色）になる
- 代表色は物体（GPUScene のインスタンス番号）ごとに最大 4096 個まで覚えておく。
  物体を消したり入れ替えたりしたあとに古い色が映る場合は「蓄積をリセット」を押す（代表色の表も空になる）
- ガラスも影を落とす（シャドウレイでは不透明として扱う）
- マテリアルの透過（Masked）で抜けている部分は、カメラから直接見える場所だけ通り抜ける（GBuffer と比べて判定する）。
  影・映り込み・反射の先では不透明の板として扱われる（AnyHit シェーダーでマテリアルを評価できないため）
